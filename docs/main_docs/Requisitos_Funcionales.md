# Requisitos funcionales propuestos para DevFlow

- RF-01 — Registro de usuarios
El sistema deberá permitir al Administrador registrar usuarios en la plataforma.

- RF-02 — Gestión de equipos
El sistema deberá permitir al Administrador crear y administrar equipos de trabajo y sus miembros.

- RF-03 — Asignación de roles
El sistema deberá permitir al Administrador asignar roles a los usuarios.

- RF-04 — Gestión de permisos
El sistema deberá permitir al Administrador administrar los permisos asociados a los roles del sistema.

- RF-05 — Creación de proyectos
El sistema deberá permitir al Project Manager crear proyectos.

- RF-06 — Administración de proyectos
El sistema deberá permitir al Project Manager modificar la información de los proyectos que administra.

- RF-07 — Consulta de proyectos
El sistema deberá permitir a los usuarios autorizados consultar la información de los proyectos a los que tengan acceso.

- RF-08 — Creación de tareas
El sistema deberá permitir al Project Manager crear tareas dentro de un proyecto.

- RF-09 — Modificación de tareas
El sistema deberá permitir al Project Manager modificar la información de las tareas pertenecientes a los proyectos que administra.

- RF-10 — Asignación de responsables
El sistema deberá permitir al Project Manager asignar responsables a las tareas.

- RF-11 — Definición de prioridad
El sistema deberá permitir al Project Manager definir la prioridad de las tareas.

- RF-12 — Definición de fecha límite
El sistema deberá permitir al Project Manager establecer fechas límite para las tareas.

- RF-13 — Actualización del estado
El sistema deberá permitir a los colaboradores actualizar el estado de las tareas que tengan asignadas.

- RF-14 — Consulta de tareas
El sistema deberá permitir a los miembros de un proyecto consultar las tareas a las que tengan acceso.

- RF-15 — Registro de comentarios
El sistema deberá permitir a los miembros autorizados registrar comentarios en las tareas.

- RF-16 — Adjuntar archivos
El sistema deberá permitir a los miembros autorizados adjuntar documentos o archivos relacionados con las tareas o proyectos.

- RF-17 — Consulta de documentación
El sistema deberá permitir a los usuarios autorizados consultar los documentos asociados a los proyectos.

- RF-18 — Consulta del progreso
El sistema deberá permitir a los Project Managers consultar el progreso de los proyectos que administran.

- RF-19 — Supervisión de proyectos
El sistema deberá permitir a los Directores o Gerentes consultar el estado de los proyectos de la empresa.

- RF-20 — Indicadores generales
El sistema deberá proporcionar a los Directores o Gerentes un panel con indicadores generales sobre los proyectos.

- RF-21 — Indicadores del colaborador
El sistema deberá permitir a los colaboradores consultar indicadores relacionados con su trabajo.

- RF-22 — Consulta limitada del cliente
El sistema deberá permitir a los clientes consultar el progreso de los proyectos a los que tengan acceso, sin exponer información no autorizada.

- RF-23 — Registro de actividades
El sistema deberá registrar las actividades relevantes realizadas sobre los proyectos y sus tareas.

- RF-24 — Consulta del historial
El sistema deberá permitir a los usuarios autorizados consultar el historial de actividades correspondiente a los proyectos.

# Requesitos NO funcionales propuestos para DevFlow

- RNF-01 — Facilidad de uso
El sistema deberá proporcionar una interfaz fácil de comprender y utilizar para los diferentes perfiles de usuario.

- RNF-02 — Interfaz intuitiva
La interfaz deberá presentar las funcionalidades de manera clara y consistente, facilitando la navegación entre proyectos, tareas y demás secciones.

- RNF-03 — Acceso web
El sistema deberá funcionar como una aplicación web sin requerir la instalación de software adicional por parte del usuario.

- RNF-04 — Compatibilidad con navegadores
El sistema deberá ser accesible desde navegadores web modernos.

- RNF-05 — Autenticación
El sistema deberá verificar la identidad de los usuarios antes de permitir el acceso a funcionalidades protegidas.

- RNF-06 — Control de acceso
El sistema deberá restringir el acceso a información y funcionalidades según los roles y permisos del usuario.

- RNF-07 — Protección de información
El sistema deberá proteger la información almacenada y transmitida contra accesos no autorizados.

- RNF-08 — Acceso de clientes
El sistema deberá impedir que los clientes accedan a información de proyectos para los cuales no posean autorización.

- RNF-09 — Crecimiento del sistema
El sistema deberá permitir incorporar nuevas funcionalidades sin requerir una reconstrucción completa de la plataforma.

- RNF-10 — Crecimiento de usuarios y proyectos
La solución deberá permitir aumentar la cantidad de usuarios, equipos y proyectos sin comprometer significativamente su funcionamiento.

- RNF-11 — Tiempo de respuesta
El sistema deberá proporcionar tiempos de respuesta adecuados durante las operaciones habituales.

- RNF-12 — Disponibilidad
El sistema deberá permanecer disponible durante los períodos en los que la empresa requiera utilizarlo.

- RNF-13 — Integridad de información
El sistema deberá preservar la consistencia de la información almacenada y evitar pérdidas o modificaciones no autorizadas.

- RNF-14 — Mantenibilidad
La solución deberá estructurarse de manera que facilite la corrección de errores y la incorporación de nuevas funcionalidades.

- RNF-15 — Documentación técnica
El sistema deberá contar con documentación técnica suficiente para facilitar su instalación, configuración y mantenimiento.
